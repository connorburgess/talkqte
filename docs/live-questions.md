# Ask about recent discussion

The notebook's **Transcript** tab shows the current session's available lines. **Ask** lets the person explicitly send a question about a bounded recent excerpt while capture continues, or after this current session ends. The floating companion's **Transcript and Ask** button opens and focuses the notebook transcript; the adjacent **Ask** tab opens questions; passive cues keep their existing focus behavior. No transcript or answer is added to the companion payload.

Opening either panel sends nothing to a model. Beside **Send**, Ask names the selected cue provider/model and the number of lines and latest timestamp of its frozen excerpt. **Transcript scope and cost** expands the exact time range, exclusions and estimated maximum cost. **Send** authorizes only that question and that disclosed excerpt; the older recent-six-line automatic-cue permission does not authorize Ask. There is no repeated review modal and no requirement to stop capture. **Use latest transcript** refreshes the excerpt without sending it. New arriving speech never silently extends a prepared request.

The first slice uses at most the latest 200 available lines within a 64 KiB serialized input bound. Older discussion is excluded, and speech may also be missing because of transcription or capture gaps. This is not whole-meeting retrieval. A question such as “What did we decide at the start?” cannot be answered from an excluded beginning. The model is instructed to explain insufficient evidence, rather than invent a plausible earlier decision. Structural validation and authored fictional replies do not prove that a live model follows this instruction.

Only the question and excerpt's IDs, timestamps and text are sent. Speaker names/roles, imported context, saved notes and previous answers are excluded. The selected provider's own key stays in Rust. The fixed HTTPS transports, redirect restrictions and bounded stream parsers are reused; no webview API key, arbitrary endpoint or generic chat relay exists. Model answers are labeled separately from transcript facts, rendered as plain text and link back to checked current transcript IDs/timestamps. Citations establish a supplied source exists, not that a model's synthesis is true. An evicted line is labeled unavailable.

Rust owns the frozen ticket, one physical Ask worker, cancellation, 30-second deadline, two-second request interval and limits: 20 dispatches/session, 1,200 output tokens, 2,400 answer characters and at most six distinct citations. A substantive answer requires citations; an insufficient-evidence answer has none. Unknown/custom unpriced models are refused rather than silently replaced. The conservative input/output estimate reserves at most $0.25 per question and $1.00 per session. Failed/cancelled dispatches retain that reservation. These are local limits based on the built-in price table, not provider billing guarantees or shared cue/notes budgets.

**Cancel answer**, **Stop**, processing **Off**, a new session or engine replacement withdraw an in-flight answer. A retired result cannot populate another session or mark its key rejected. A previously sent remote request cannot be recalled and may be billed; a cancelled transport retains the single worker slot until it exits. A new explicit Send after Stop or Off is a separate approval for its shown scope. Cue **Pause** suppresses automatic cues independently; it does not cancel an explicitly requested answer or stop capture. Failed questions remain editable for an explicit retry; there are no automatic retries.

The most recent ten successful Q&A entries remain in memory for this session only. New sessions clear them; quitting loses them. They are not added to transcripts, kept meetings, generated notes or exports. Leaving the Ask tab cancels its pending answer. Saving answers, asking across saved meetings, whole-session retrieval and conversational follow-up history are not implemented.

Offline Rust tests exercise lifecycle, scope, cost/rate/output/citation and delayed-auth boundaries. Fictional Chromium/WebKit tests exercise Send, cancel/retry, IME, narrow rendering, source navigation and preserving a transcript reader's scroll position. These do not prove live model usefulness, provider retention, actual network cancellation, native cross-application focus or native assistive access. Next acceptance: a separately authorized fictional live-provider question with an included fact and an excluded beginning, plus native dock-to-notebook keyboard/focus and Stop checks, with measured cost/latency and no private data.
