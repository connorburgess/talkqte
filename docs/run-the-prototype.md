# Run the prototype

What the current prototype does once it is running, with its limits. Setup is in the [README](../README.md#run-the-current-prototype); the developer-only live session is in [Live session](../README.md#live-session-developer-build).

The notebook opens with a short **Before your first meeting** card: your name, what matters today, the speech model when the build can use one, and prior notes; it steps aside once the required steps are done, or with **Not now** for the session, and returns on the next launch because nothing is kept between launches. The moments TalkQTE acts on are small and concrete: someone asks you something by name, someone says a date or commits to one, or the conversation touches a note you brought. Choose **Try demo** for the fictional community-garden conversation. It requires no capture permission, model download, or API credentials. Open **Why?** to inspect a question's source and keep it available while reading; **Dismiss** clears it. Untouched questions pass quietly. When someone says a date or commits to one ("ready by Friday", "legal takes two days"), the companion quotes that sentence word for word as a **Said** cue instead of paraphrasing it, because "ready by Friday" is not "starting Friday"; **Keep this line** puts the quote, with its time and speaker, into your notes, and nothing is kept unless you press it. New questions expand briefly, with a reduced-motion alternative. Settings provides text size, timing, companion placement, and a session-only name used to notice questions asked of you in a live session. The notebook's **This meeting** box, beside the session controls, holds the focus list, up to five short lines on what matters in this meeting, with **Clear** to start the next meeting fresh: when a line uses a focus line's words, a question about it comes through even during the pause after another question and stays 45 seconds, the length of a question asked of you by name; a topic change still withdraws it. The **Focused** timing setting, also a switch on the companion's bar, shows only those questions, questions asked of you by name, and reminders of notes you chose, so a meeting that drifts leaves the companion quiet; when someone says the meeting is wrapping up, the focus lines the conversation never touched are listed once. A session shows at most three note reminders. All of these are word matches, kept only until you quit.

The companion is configured not to take keyboard focus; use the notebook for keyboard controls. Drag it by its top bar to put it anywhere on the display; choosing a position in Settings moves it back. Dismissal there returns focus to notes or the selected Transcript tab unless you have already moved elsewhere. Cross-app focus and native placement still have [pending checks](native-validation.md). See [Glance view](glance-mode.md) for the current hold and expiry behavior.

**Prior context from a file:** the notebook's **Add notes from a file** reads a small JSON notes file you choose (a `notes` list with an `id`, `date`, and `text` for each note; up to 1 MB and 200 notes are read, and up to 20 can be kept), lets you tick the notes to keep, and shows them beside your notebook labeled as not from this conversation. They stay in memory for the session, can be removed one by one or all at once, and are never exported. When a line of the conversation uses two or more distinctive words from a note's title, the companion shows that note once as a reminder, labeled with its date and "not from this conversation"; this is a phrase match on the title, not a judgment of relevance, and whether such reminders help is an untested hypothesis. **Prior context from Granola:** in the desktop app, **Connect Granola** signs you in to your own Granola account in your browser (OAuth, with a return to the app on this Mac) and keeps the sign-in in memory until you quit or disconnect; **Choose Granola notes** then lists your notes of the last 30 days, the window Granola's free plan allows, and only the notes you tick are brought in, through the same chooser and with the same limits as a file. TalkQTE asks Granola for its note list, the ticked notes, and, if you ask for suggestions, one fixed question; it reads no transcripts (a paid Granola feature) and writes nothing back. The connection follows Granola's documented MCP server ([integration plan](product-readiness.md#integration-readiness)); it has been exercised against a fictional server in tests and not yet against a real account, so the fields of a real note may differ from what the chooser shows. When the connected account offers Granola's assistant (the `query_granola_meetings` tool, which depends on the plan), the **This meeting** box adds **Suggest from Granola** under the focus list: TalkQTE asks the assistant one fixed question about your meetings of the last 30 days (open decisions, tasks nobody has taken on, unanswered questions; short lines, no names) and shows the answer as suggestions you tick before any becomes a focus line. This is the only place TalkQTE uses a language model today (the speech model runs locally), it is Granola's model on Granola's side, it runs only when you press the button, and a suggestion is Granola's reading of your notes, not a fact.

**Demo notes are kept in memory until you quit.** Review and export anything you want to retain. Optional notes and export support prototype exploration; saving generated cues is not part of the live flow.

<details>
<summary>Microphone activity and development commands</summary>

Choose **Start microphone** explicitly and grant macOS permission if prompted. **Stop microphone** releases the input device; the stopping state remains until release completes. Pausing or ending the fictional demo does not stop monitoring. Hiding the companion only hides its window. The monitor does not retain samples, upload audio, hear the other side of a call through system audio, or generate cues. The browser preview cannot monitor a microphone. On one Mac, the permission prompt, signal activity, and Stop releasing the microphone have been checked ([record](native-validation.md#microphone-activity-check)); permission denial, device disconnect, and other setups remain unchecked.

`npm run dev` serves a separate browser simulation at `http://127.0.0.1:1420`. `npm test` runs browser behavior checks; `npm run build` builds the frontend. Browser checks do not verify Rust IPC or native windows.

`APPLE_SIGNING_IDENTITY=- npm run tauri -- build --debug --bundles app` builds an ad-hoc-signed local development app. It is not a Developer ID-signed or notarized release.
