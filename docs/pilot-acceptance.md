# Pilot and wider-release acceptance criteria

Status: proposal, 9 November 2026, for the owner to agree before any pilot is planned. Nothing here invites anyone to a pilot or promises a release. It turns the [release stages](product-readiness.md#release-stages-and-acceptance) and the [milestone acceptance](initial-rollout.md) into checks that pass or fail, so "ready" is not a feeling. Each row names how the check is run and what has been done so far. "Not started" means exactly that.

Two gates are defined. The **invited pilot** gate is what a small number of invited people need before they are asked to try a build on their own Macs. The **wider release** gate is what a public download would need. Meeting the first gate does not start a pilot; recruitment is a separate decision ([product readiness](product-readiness.md#distribution-and-first-use)).

## How to read a criterion

- **Pass** needs the stated evidence, recorded in this repository with fictional content, a build commit, and the setup used.
- A green test suite, a fictional demo, or a successful build is never sufficient on its own.
- Observations of usefulness come from people; synthetic measurements do not stand in for them.

## What the owner needs to decide

- Agree or change these criteria, and set the open thresholds: the minimum number of pilot participants, the minimum effect for a wider release, and the acceptable false-suppression rate.
- The Apple Developer Program membership and custody of the signing key, without which the installation criteria cannot start.
- Whether a pilot build may offer a Granola connection; if not, the connection row does not apply to the pilot.

## What this is not

It is not a schedule, and it does not change what the public site says: a fictional concept preview and an invitation to follow development. No criterion here is met by the demo, by a mock integration, or by this document.
